CoCo Design System · v2

One language, two modes.

The same tokens and components power a calm light mode for customers and managers, and a high-contrast field mode for drivers and collectors. Everything here is live CSS from the prototype — not a picture of it.

Status first

Every screen answers "what's happening right now?" before anything else. Status has one vocabulary across all four apps.

Built for the field

Gloves, glare, vibration and a moving truck. Field screens get 56px targets, one primary action, and glanceable type.

One system, many contexts

Semantic tokens flip between light and field-dark. Components never reference raw colors, so both modes stay in sync.

Progressive by default

Ask only what's needed to start service. Secondary features stay reachable but never compete with the core loop.

Color

Three tiers: primitives (raw scales), semantic tokens (what a color means), and component usage. Build with semantic tokens only.

Brand blue

blue-500 #007AFF is the brand color — logo, display type, map routes. Interactive fills use blue-600 (4.75:1 with white) and blue text uses blue-700 (5.42:1 on white).

Status system

Status is the product. Each state maps to exactly one chip treatment, used identically by every role — a customer's "Pick up complete" is the same object the collector created.

Icons

24px grid, 2px round strokes, inherit currentColor. Pair every status icon with a text label. Click an icon to copy its name.

Buttons

Pill-shaped. One primary per screen. Field screens use .btn--field (56px) and full-width placement at the thumb zone.

Status chips

The most-used component in CoCo. Default 28px; .chip--lg (40px) for the primary status on a card.

Cards & metrics

Cards group one idea. Hero cards carry the current status; metric cards carry one number with context. In field mode cards swap shadows for 1px borders.

Form controls

52px inputs with visible labels (never placeholder-only). Choices are big tappable cards; binary settings are toggles.

Progress tracker

The vertical timeline is CoCo's signature pattern — pickup tracking, route queues, pickup history and fleet activity all use it. Nodes are numbered for queues and iconic for states.

Lists & tables

Lists for navigation and settings. Tables only from 900px — on phones, the same rows collapse into cards.

Feedback

Alerts explain what happened and what to do. Toasts confirm an action and disappear. Nobody should find out about a delay after the fact.

Navigation

Bottom tab bars on phones (max five, one optional center action). The fleet dashboard promotes to a sidebar at 900px. The round blue menu button from v1 is kept as the brand anchor in the app bar.

Field mode rules

Drivers and collectors use CoCo in motion, outdoors, often wearing gloves. Field mode is more than a dark theme.

One instruction, one action

The drive screen shows a single turn instruction and a single primary button. Everything else is a tab away.

56px minimum targets

All field buttons, quick replies and check rows are at least 56px tall and full-width in the thumb zone.

Glare-safe accents

Accents shift to lighter tints (blue-400, green-300) on #212121 surfaces for 6:1+ contrast without neon glare at night.

Talk, don't type

Crew messaging leads with quick replies and push-to-talk. The keyboard is the fallback, never the default.

Usage

Plain CSS, no build step. Load the three layers in order and set a theme on any container.

<link rel="stylesheet" href="assets/css/tokens.css">
<link rel="stylesheet" href="assets/css/base.css">
<link rel="stylesheet" href="assets/css/components.css">

<!-- Any subtree can switch mode -->
<section data-theme="dark">
  <span class="chip chip--ok">…Ready for pick up</span>
  <button class="btn btn--field btn--block">Arrived at stop</button>
</section>
import { icon } from './assets/js/icons.js';
el.innerHTML = icon('truck');   // inline SVG, inherits currentColor
